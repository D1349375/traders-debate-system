

> 使用女媧skill蒸餾長期獲利交易員的思維框架，透過多人格辯論產生 Daily/Weekly Bias，並長期回測驗證準確率。

---

## 專案總覽

```
Phase 0 篩選交易員 → Phase 1 資料蒐集 → Phase 2 人格蒸餾 → Phase 3 辯論機制 → Phase 4 回測系統 → Phase 5 迭代優化
```

**建議落地順序**：先用 1 位交易員跑完 Phase 0-2 POC → 驗證蒸餾品質 → 擴展多人格辯論(Phase 3) → 接上正式回測(Phase 4) → 進入迭代循環(Phase 5)。

---

## Phase 0：交易員篩選

**目標**：篩選 3-5 位適合蒸餾的公開交易員原型

|工作項|內容|產出|
|---|---|---|
|0.1 篩選標準定義|帳號歷史 ≥2-3年、發文含明確方向判斷、流派多元(總經/技術/籌碼/情緒)|篩選標準文件|
|0.2 候選名單建立|從 X/Threads 搜尋符合標準的帳號，初篩 10-15 位|候選名單(含帳號、發文量、活躍時間)|
|0.3 事後可驗證性檢查|抽樣其過去判斷 vs 實際行情，排除模稜兩可型帳號|最終 3-5 位交易員名單|

**驗收標準**：每位入選交易員需有 ≥200 篇含明確方向判斷的歷史貼文。

## Phase 1：資料蒐集

### 1.1 技術架構

```
[X API v2 / Threads API] → [資料抓取層] → [清理/標註層] → [結構化儲存 (DB)]
```

|元件|技術選型建議|說明|
|---|---|---|
|資料源|X API v2 (Basic/Pro tier)|官方付費方案，合法抓取指定帳號歷史推文，避免爬蟲違反 ToS|
|資料源|Threads API|官方 API 較新，歷史深度需實測，可作補充來源|
|儲存|PostgreSQL / SQLite(POC階段)|結構化欄位見下方 schema|
|排程|Cron / Airflow(視規模)|定期增量抓取新發文，供後續持續蒸餾更新用|

### 1.2 資料 Schema

```
posts (
  id, trader_id, platform, posted_at,
  raw_text, target_asset,
  inferred_direction (多/空/中性),
  inferred_timeframe (日內/週/月),
  price_at_post,
  price_after_1d, price_after_5d, price_after_20d  -- 供 Phase 4 回測用，現在就記錄
)
```

### 1.3 工作分解

|工作項|內容|產出|
|---|---|---|
|1.1 API 串接|申請 X API 存取權限，寫抓取腳本|可執行的抓取程式|
|1.2 資料清理|過濾純轉發/純圖表貼文|清理後語料庫|
|1.3 方向標註|LLM輔助標註方向/時間框架 + 人工抽查|標註後資料集|
|1.4 價格對齊|抓取貼文當下與後續N天標的價格，寫入 schema|完整訓練/回測資料集|

**驗收標準**：每位交易員至少 200 篇已標註、已對齊價格的貼文。

## Phase 2：人格蒸餾(女媧skill)

### 2.1 流程

```
清理後語料 → 餵給女媧skill蒐集流程(替代原本著作/訪談來源)
           → 女媧6-Agent並行提取(心智模型/決策啟發式/表達DNA)
           → 三重驗證(跨場景重複出現 + 有預測力 + 有排他性)
           → 產出 SKILL.md 人格檔案
           → 回測驗證(用該交易員本人真實歷史情境測試人格輸出一致性)
```

### 2.2 工作分解

|工作項|內容|產出|
|---|---|---|
|2.1 女媧skill安裝與設定|`npx skills add alchaincyf/nuwa-skill`|可用環境|
|2.2 語料匯入|將 Phase 1 語料格式化為女媧可讀輸入|匯入腳本|
|2.3 逐一蒸餾|對每位交易員執行蒸餾流程|N 個交易員人格 SKILL.md|
|2.4 一致性驗證|用該交易員過去實際判斷過的情境，測試人格輸出是否吻合|一致性報告(逐人格準確率)|

**驗收標準**：每個人格在「已知歷史情境重放測試」中，方向判斷與交易員本人實際判斷的一致率 ≥60%(門檻可依實測調整)。低於門檻的人格需回頭補資料或淘汰。

## Phase 3：辯論機制設計

### 3.1 技術架構

```
[市場數據摘要生成器] → [各人格獨立判斷] → [交叉點評] → [裁判/加權層] → [結構化 Bias 輸出]
```

|元件|說明|
|---|---|
|市場數據摘要生成器|統一格式：價格位置、近期波動率、關鍵事件、成交量異常等，餵給所有人格的共同輸入|
|獨立判斷層|每個人格各自輸出：方向、信心分數(0-100)、理由|
|交叉點評層|讓各人格看到彼此判斷後，進行一輪回應/反駁|
|裁判/加權層|初期：簡單多數決或信心加權；中後期：依 Phase 4 累積的歷史準確率動態加權|

### 3.2 輸出格式

```json
{
  "date": "2026-07-13",
  "asset": "...",
  "daily_bias": "多/空/中性",
  "weekly_bias": "多/空/中性",
  "confidence_score": 0-100,
  "persona_opinions": [
    {"trader": "...", "direction": "...", "confidence": ..., "reason": "..."}
  ],
  "disagreement_points": ["..."]
}
```

### 3.3 工作分解

|工作項|內容|產出|
|---|---|---|
|3.1 市場數據串接|接入行情API，產生標準化市場摘要|摘要生成模組|
|3.2 辯論流程開發|串接多個人格 SKILL、設計交叉點評 prompt|辯論引擎|
|3.3 裁判邏輯 v1|簡單多數決/信心加權版本|可運行的 bias 產出流程|
|3.4 每日/每週排程|自動化每日產出並儲存輸出|排程系統|

**驗收標準**：系統能每日/每週自動產出結構化 bias 記錄，並完整保存各人格意見供後續分析。

## Phase 4：回測系統

### 4.1 核心原則

- **Walk-forward 驗證**：只用產生bias當下能取得的資訊，禁止用蒸餾階段已知的未來事件
- **避免資料洩漏**：人格蒸餾用的語料時間範圍需早於回測起始日，或做嚴格的時間切割
- **多維度追蹤**，而非單一準確率數字

### 4.2 追蹤指標

|指標|說明|
|---|---|
|方向準確率|Daily/Weekly bias 對照實際走勢的命中率|
|信心校準度|信心分數80%的判斷，實際命中率是否真的較高(calibration curve)|
|個別 vs 綜合|單一人格準確率 vs 辯論後綜合bias準確率，驗證辯論是否有加值|
|分歧情境表現|人格間分歧大的日子，bias 準確率是否反而較低(可作為信心度輔助指標)|

### 4.3 工作分解

|工作項|內容|產出|
|---|---|---|
|4.1 回測框架搭建|Walk-forward 記錄比對系統|回測引擎|
|4.2 指標計算模組|準確率、校準度、個別vs綜合對比|指標儀表板|
|4.3 最小樣本期執行|持續運行 3-6 個月，多標的分散樣本|初步回測報告|
|4.4 統計顯著性檢驗|對照隨機/簡單基準(如純多頭偏誤)判斷是否有真實 alpha|統計檢定報告|

**驗收標準**：累積至少 3-6 個月、多標的的 walk-forward 記錄，且有對照基準組(baseline)可比較。

## Phase 5：迭代優化

|工作項|內容|頻率|
|---|---|---|
|5.1 人格表現複檢|檢視準確率低的人格是蒸餾失真或該交易員近期失準|每月|
|5.2 裁判權重調整|依累積回測數據動態調整各人格辯論權重|每月|
|5.3 交易員汰換/補充|持續失準者汰換，補充新原型|每季|
|5.4 語料更新|增量抓取交易員新發文，重新蒸餾更新人格|每季|

## 風險與已知限制(需持續留意)

1. **資料稀缺性**：真正頂尖且長期公開發表明確判斷的交易員數量有限，樣本可能不夠多元
2. **敘事 vs 訊號落差**：蒸餾出的是語言化的決策邏輯，非可直接量化的訊號，轉換過程可能失真
3. **回測樣本量**：Daily/Weekly bias 樣本天生有限(一年約250個交易日)，統計顯著性需要長時間累積或多標的並行
4. **Look-ahead bias**：蒸餾語料與回測期間的時間切割必須嚴格執行，否則回測結果會虛高
5. **本專案定位建議**：初期以「輔助決策的機率參考/研究工具」為目標，而非直接自動化交易訊號
